## 3. Hard rules and preferences

- **No tomatoes.** Never suggest tomatoes, tomato sauce, salsa, pico de gallo, ketchup or tomato-based
  dishes. Offer non-tomato alternatives.
- **Žemaitijos varškė** without a variant = **liesa 0,5 %** (96 kcal, 20 g protein /100 g).
- "Amfora greek yoghurt" = Graikiška Amfora natūralus (assume 3,9 %).
- He **weighs food** and lists every sauce he adds when cooking at home — if a sauce isn't in his
  note, it isn't in the dish.
- Prefers simple, high-protein, low-processing food; likes seeing grams and per-portion nutrition.
- Avoid: processed meat (sausages, ham, "no added E" sausages are still NOVA 4C), mayonnaise-based
  dressings, battered/fried dishes, sweet glazes, tortillas, store pastries.
- Planned small treats are fine (e.g. 1/5 of a cake slice); judge entries relative to targets — don't
  call a good dish "the weakest" just because it scored lowest on a clean day.
- Mild hunger is acceptable; push extra food only when the deficit heads past ~500 kcal.

## 7. Where the data lives (same environment, key already set)

All calls need `?key=$SUVALGIAU_BRIDGE_KEY` (env var). **Never print the key or write it to a tracked
file.**

| Need | Call |
|---|---|
| One day's entries, totals, Garmin, existing summary | `curl -s "https://perkubulve.lt/suvalgiau/day.php?key=$SUVALGIAU_BRIDGE_KEY&user=2&date=YYYY-MM-DD"` → `entries[]` (note, calories, protein_g, fiber_g, carbs_g, fat_g, NOVA, score), `stats` (totals), `garmin`, `activities`, `existing_summary` |
| Which days have entries | `curl -s "https://perkubulve.lt/suvalgiau/pending-days.php?key=$SUVALGIAU_BRIDGE_KEY&all=1&user=2"` |

| Product NOVA + ingredients (no key) | `curl -s "https://valgau.perkubulve.lt/api.php?action=list&q=<name>"` then `...&action=product&id=<id>` |

Notes:
- **Today's** Garmin step/calorie counters are stale (manual morning sync) — don't use them; today's
  overnight sleep/HRV/resting-HR are fine.
- Run any Python that parses downloaded data with `python3 -I`; keep scratch files in the session

## 8. How to update this file

1. Work on branch **`claude/project-explanation-ms0hvn`**: `git fetch origin claude/project-explanation-ms0hvn && git checkout claude/project-explanation-ms0hvn && git pull`.
2. **Before** relying on the file, pull so you have the other session's latest edits.
3. Edit the relevant section (preference → §3, new staple → §4, recipe → §5, context → §6, new
   targets after a calibration → §2). Keep it factual and dated.
4. Commit and push right away:
   `git add FOOD-PROFILE.md && git commit -m "Food profile: <what changed>" && git push -u origin claude/project-explanation-ms0hvn`
   (retry on network errors with 2/4/8/16 s backoff). If the push is rejected, `git pull --rebase`
   and push again.
5. Don't put model names, keys or other users' food details into the file.
